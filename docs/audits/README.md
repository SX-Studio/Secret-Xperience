# Audits

Point-in-time reviews. Each one describes the platform **on the date in its header**, not as
it is today, so read the date first and check anything that has moved since.

| File | Date | Scope |
|---|---|---|
| `PLATFORM_AUDIT.md` | 2026-05-23 | Full platform review, item by item with a RAG status. |
| `MARKETING-AUDIT.md` | 2026-06-06 | Marketing and SEO review, built from the application source. |

A new audit is added as a new dated file. Superseded ones move to `archive/` rather than
being overwritten, so the trail of what was found when stays intact.
